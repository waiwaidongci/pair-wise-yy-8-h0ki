# 古法纸浆发酵与洗浆领用

运行：

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-pulp-fermentation.json`。

## 三块分开维护

1. **发酵批次**：只记发酵天数与状态（入缸 / 发酵中 / 可抄纸 / 异常观察），可登记入缸浆量、负责人和每日观察。
2. **洗浆复核**：批次进入“可抄纸”后逐缸登记洗浆记录——洗浆水量、滤水浊度、操作人。
   - 水量低于规则下限或浊度高于二度，该缸转 **待复洗**，不合格复核 **不占领用量**。
   - 换人连续两次浊度合格、相隔不少于四小时（滑动窗口判定），该缸才成为 **可领用**。
   - 页面可按“待复洗 / 可领用 / 待复核 / 已领完 / 未到复核”筛选。
3. **领用台账**：领用量不得超过剩余浆量；开具领用单后自动更正洗浆记录、原许可标记失效，再次领用须重新换人双复核。台账只增不改，旧领用单保留可查。
4. **批次规则**：最低洗浆水量、浊度上限、连续合格次数、相隔小时数、是否须换人均可在此调整；规则修改后许可状态按现规则即时重算。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/items` | 发酵批次列表 / 建档（可带 `pulpAmount` 入缸浆量） |
| PATCH | `/api/items/:code` |更正批次状态或补登浆量 |
| POST | `/api/items/:code/action` | 每日观察，自动累加天数并判定状态 |
| GET/PUT | `/api/rules` | 读取 / 更新批次规则 |
| GET/POST | `/api/washes` | 洗浆记录 / 登记一次逐缸复核 |
| GET | `/api/wash-summary` | 每缸复核状态、许可复核链与剩余浆量 |
| GET/POST | `/api/requisitions` | 领用台账 / 开具领用单（服务端校验全部领用条件） |
